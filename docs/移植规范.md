# 旧流水线 → Python 任务模块 移植规范

把 `assets/resource_picli/base/pipeline/*.json` 里的每个游戏功能，改写成
`PyPipeline/Tasks/` 下的一个 Python 模块。目标是**可读的 Python 控制流**，
不是把 JSON 换个语法再写一遍 —— 遇到「绕圈子的 pipeline 写法」，直接用
Python 表达原本的意图。

## 硬性要求

1. **一个游戏功能一个模块**，文件名用英文小写下划线，如 `dispatch.py`、`research.py`。
   一个功能原来的多个 JSON（比如 `7_training.json` + `7_(02)level.json` +
   `7_(03)allin.json`）合并进同一个模块，不要拆成互相 import 的多个模块。
2. **模块之间不许互相 import**。共用的东西要么放进 `MWATools`（像
   `EXCEPTION_CANDS` / `QUIT` / `MAIN_PAGE` 那样），要么在本模块内重复定义一份。
   这条是「互不干扰」的地基：任何一个模块坏掉，其它模块照常加载、照常跑。
3. **只从 `MWATools.MWATask` 和 `MWATools.MWAScreen` 里取东西**，不要在任务模块里
   直接 `import maa`、不要自己建 `Tasker`／`Controller`／`Resource`。
4. 任务 key **必须和 `assets/interface.json` 里的 task `name` 一字不差**
   （例如 `"派遣公司"`、`"给好友点赞（目前默认就前4个）"`）。写得不一样，旧流水线
   注册那边就不会自动让位，会出现两个同名任务。
5. 原来有 option 的任务，option 的 **key、label、case 名、默认值** 都要和
   `assets/interface.json` 对齐（默认值 = `default_case`，没写就是第一个 case）。
6. 图片模板的路径**用正斜杠**（`"Startup/10.png"`，不是 `"Startup\\10.png"`）。
   路径一律当作**资源包 `image/` 目录下的相对路径**写。
7. `python3 -m py_compile <文件>` 必须通过；`PyPipeline.Tasks.load_all()` 必须能
   把模块 import 进去（不能有拼错的函数名、不能在模块顶层做 IO）。

## 可用的 API（全都在 `MWATools.MWATask` 里）

```python
from MWATools.MWATask import (
    Choice, Option, TaskContext, task,
    OCR, IMG, ANY, Cand,            # 候选项构造器
    MAIN_PAGE, QUIT, LOADING_WORDS, EXCEPTION_CANDS, handle_exceptions,
)
```

### 声明任务

```python
@task("派遣公司",                       # 任务 key —— 必须和 interface.json 一致
      group="日常",                     # UI 分组
      order=100,                       # 排序，小的在前
      options=(某个选项, ...),           # 没有就不写
      default_enabled=False,           # 是否默认勾选
      description="一句话说清它干什么")
def 派遣公司(ctx: TaskContext) -> bool:
    ...
    return True      # 走完了
    return False     # 中途放弃（比如当前不在该界面），不算报错
```

### 候选项与步骤

```python
OCR("全部")                              # 文字识别，命中就点它
OCR(["衣装上新", "周边上新"])              # 词表：任一命中即可
OCR("今日登录不再提示", roi=(115, 590, 277, 100))          # 只在 roi 里找
OCR("得", delay=2000)                    # 点完等 2000ms
IMG("Mainpage/mail.png")                 # 模板匹配
IMG("Startup/10.png", roi=(0, 0, 500, 300), threshold=0.8)
OCR("全部", point=(1160, 130))            # 识别到了但点这个绝对坐标（旧 target: [x,y,0,0]）
IMG("Collect/06.png", wait_freezes=2000)  # 点完再等画面静止
IMG("3_(5)_tea/24.png", green_mask=True)  # 旧 green_mask：先抠掉绿色再匹配
IMG("3_(5)_tea/27.png", green_mask=True, index=-1)   # 旧 index：多个命中取最后一个
OCR("全部", index=2)                      # OCR 同理，取第 3 个命中
```

`roi` 的坐标系是 **1280x720 基准**（就是旧 JSON 里 roi 的原值，照抄即可）。

### 上下文方法

```python
ctx.step("正在打开邮箱")             # 汇报进度，GUI 会显示、日志会记
ctx.look(cand) -> Match | None      # 只看一眼，不点
ctx.tap(cand) -> bool               # 看一眼，命中就点
ctx.tap_first(*steps) -> step|None  # 依次试，做成了第一个就返回它
ctx.scan(*steps, timeout=20000, interval=400, desc="") -> step|None
                                    # ★ 反复扫整张步骤表直到有一个做成，或超时
ctx.retry(fn, timeout=60000, interval=500) -> bool
ctx.wait_for(fn, timeout=20000, interval=400) -> bool
ctx.back(delay=800)                 # 按返回键
ctx.check_cancel()                  # 长循环里调，被用户中断就抛 TaskCancelled
ctx.option / ctx.text / ctx.flag / ctx.number   # 读选项
ctx.screen.click((x, y, w, h), delay=2000, desc="...")   # 点矩形中心（旧 target 语义）
ctx.screen.click((x, y), delay=2000)                     # 点绝对点
ctx.screen.swipe((x1, y1), (x2, y2), duration=300)
ctx.screen.press_key(4)             # Android 返回键
ctx.screen.shell("命令")             # adb shell，返回输出
ctx.screen.wait_freezes(time=2000)  # 等画面静止
```

### `scan` 的语义 = 旧 `next` 列表

旧 JSON 里

```json
"some_node": { "next": ["A", "B", "[JumpBack]Exception-handling-remind"] }
```

翻译成

```python
ctx.scan(做A, 做B, handle_exceptions, timeout=20000, desc="...")
```

`step` 既可以是一个 `Cand`，也可以是一个 `def 做A(ctx) -> bool` 的函数 ——
后者让你能把一条 `next` 链条**逐节点**写成函数，一分支都不丢。

### 共用件

* `QUIT` —— 旧 JSON 里那个被 6 个文件共用的 `Quit` 节点（模板 `Collect/06.png`，关掉当前面板）。
* `handle_exceptions` —— 旧 JSON 里满世界塞的 `[JumpBack]Exception-handling-*`
  （今日登录提示 / 养成特惠弹窗 / 误入其它界面）。它是普通函数，直接当 step 用。
* `MAIN_PAGE` —— 「已经在游戏主界面」的标记（`Startup/11.png`）。
* `LOADING_WORDS` —— 开屏读条时轮播的词，`OCR(LOADING_WORDS)` 就能判断"还在加载"。

## 风格约定

* 用**中文函数名**描述业务动作（这个项目里到处都是中文标识符，保持一致）。
* 每个函数上面用一行注释标出它对应旧 JSON 的哪个节点名，例如
  `"""旧节点 ``dissect_button``。"""`
* 注释解释**为什么**这么做，而不是复述代码。
* 别把 JSON 里的 `post_delay` 丢掉 —— 那些延时是游戏界面动画需要的。
* 旧写法里绕圈子的地方（比如「空节点 + 靠 option 覆盖 next 来选分支」），
  直接用 Python 的 `if` / 字典查表表达，并在注释里说明原来的绕法。

## 常见陷阱（血泪教训，移植时逐条自查）

### 1. 没有 `action` 字段的节点 = **只识别，不点击**

maafw 的 `action` 默认值是 **`DoNothing`**，不是「识别到就点它」。

> `.tmp_maadocs/pipeline.md:198-200`：``action``: *string* 执行的动作。可选，默认 `DoNothing`。

旧 JSON 里大量节点只挂了 `recognition` + `next`，作用是「认一下当前在哪，认到了就去走自己的 next」。
这类节点在 Python 里必须是 **`ctx.look(...)`** / `ctx.screen.find(...)`，命中后 `return True` 走下一步；
**写成 `ctx.tap(...)` 就是行为变更**（会多点一下，可能弹出面板或跳转，把流程带偏）。

自查方法：

```python
import json, pathlib
d = json.loads(pathlib.Path("assets/resource_picli/base/pipeline/XXX.json").read_text(encoding="utf-8"))
print([n for n, b in d.items() if isinstance(b, dict) and "action" not in b])
```

各源 JSON 里没写 `action` 的节点数（供对照）：

| JSON | 个数 | JSON | 个数 |
| --- | ---: | --- | ---: |
| `8_resource.json` | 11 | `3_(4)_fabricate.json` | 2 |
| `11_(02)_snowscape.json` | 11 | `3_(5)_tea.json` | 2 |
| `7_(03)allin.json` | 8 | `3_(6)_vitality.json` | 2 |
| `11_2_goldresearch.json` | 7 | `14_activity.json` | 2 |
| `2_collect_operators.json` | 4 | `3-(2)_vending_machine.json` | 2 |
| `11_Research.json` | 2 | 其余 20 个文件 | 各 1 |

### 2. `next: [A, 自己]` 是自重试，不是死循环

旧 JSON 里常见 `"next": ["A", "本节点名"]` —— 意思是「点完 A 之后如果本节点该认得的东西还没出现，就再点自己一次」。
一个节点只做一件事的话，写成 `ctx.scan(A, handle_exceptions, timeout=..., desc=...)` 就够了，**不要真的递归调用自己**（会爆栈）。

### 3. 别把 `post_delay` / `post_wait_freezes` 搬丢

* `post_delay: 2000` → `Cand(..., delay=2000)`；**如果这一步不点击**，用 `ctx.screen.sleep(2000)`。
* `post_wait_freezes: 7000` → `ctx.screen.wait_freezes(time=7000)`（"等画面静止 7 秒"）。

### 4. 节点级 `timeout` 管的是 **本节点扫 `next` 的过程**

默认 20000ms。所以 `ctx.scan(...)` 的 `timeout=` 应该照抄**父节点**的 `timeout`（旧 JSON 没写就是 20000），
不是子节点的。

### 5. `[JumpBack]X` 命中后会回到父节点、从 `next` 开头重扫

这是异常处理天然获得高优先级的原因。在 Python 里体现为：把 `handle_exceptions` 放在 `ctx.scan(...)` 参数列表里，
它会和正常步骤一起被按顺序试。
